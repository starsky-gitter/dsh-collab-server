# 团队共享上下文：机制设计

目标：一个人用 AI 得出的结论，另一台机器上的 AI 能按需拿到**一条**，而不是读一整份 md。
不做 git 操作，不做原始对话同步。

## 1. 数据单位：记录（Record），不是文件

一条记录 = 一个原子结论，目标 200–600 token：

```json
{
  "id": "r_xxx",
  "project": "motor-f407",
  "kind": "fact | decision | failure | env | bench | change",
  "title": "一句话结论",
  "body": "为什么 / 怎么验证的 / 适用条件（markdown，短）",
  "scope": { "board": "F407IG", "mcu": "STM32F407", "paths": ["drivers/can/**"], "toolchain": "gcc-arm-12.2" },
  "status": "draft | verified | stale | superseded",
  "evidence": [{ "type": "serial", "label": "USART1 在 500k 下无丢帧", "ref": "log-2026-11-06.txt" }],
  "author": "张三", "sessionId": "…", "tags": ["CAN", "时序"],
  "createdAt": 0, "updatedAt": 0, "seq": 12
}
```

关键点：

- **状态是可信度**。`draft` 是 AI 草稿，`verified` 必须有人或硬件证据背书，`stale` 表示环境/版本变了可能失效。
- **scope 决定检索命中**。板卡、MCU、路径、工具链，比全文搜索可靠得多。
- **evidence 让结论可复核**。串口日志、构建产物摘要、上板结果。

## 2. 记录怎么产生（三条路，宁缺毋滥）

1. **AI 主动提交**：`team_share` 工具。系统提示里常驻一段很短的协议：得出可复用结论、硬件事实、决策或失败教训时提交；先 `team_recall` 查重；不写密钥和客户数据。
2. **人工补录**：面板里"新建记录"，给不习惯让 AI 代劳的人留入口。
3. **回合结束自动草稿**（v0.2）：`agent/turn-stopping` 时抽取本轮的工具结果与结论，生成 `draft` 进待审队列，**不自动发布**。

草稿便宜、噪声多；**审核才是质量闸门**。这是和"共享对话"最本质的区别。

## 3. AI 怎么拿到（不读文件）

- **会话开始**：注入一份"团队简报"，约 600–900 token：本项目的 `verified` 记录（id + 标题 + 一行要点）+ 待审数量。放系统提示的稳定段，可被 prompt cache 命中。
- **需要细节**：`team_recall(query, kind, status)` 返回候选记录；`team_get(id)` 取全文。
- **硬规则**：只有 `verified` 进简报；`draft` 只在面板里可见。
- **衰减**：记录的 scope 带工具链/板卡版本；读者环境不一致时标注"可能已失效"，而不是静默采用。

这样 AI 的上下文成本是 O(命中条数)，不是 O(知识库大小)。

## 4. 检索

服务端做：scope 过滤（project / kind / status / board / path）→ 词法打分（英文词 + 中文 bigram）→ 状态与时效加权 → top-k。
不引入向量库；等记录过万再加 embedding 重排，且可重建。

## 5. 同步与离线

- 服务器是记录的真相源；客户端只做读缓存。
- 增量游标 `seq`，`GET /api/records?since=` 拉增量；写失败进本地重试队列。
- 无 git、无分支、无合并冲突：记录只追加，修正靠新记录 `supersede` 或改状态。

## 6. UI

左栏一级入口（`sidebar.panellist` 图标 + `main` 页面），设置页保留同一入口作为兜底。双栏：

- 顶部：项目、在线状态、刷新、新建记录。
- 左栏：搜索框、状态筛选（全部/待审/已验证/已失效）、类型筛选、记录卡片列表（标题、类型徽标、状态点、作者、相对时间）。
- 右栏：详情（正文、scope、证据、id）、动作（通过验证 / 标记失效 / 在会话引用 / 复制 id）。
- 空态、加载态、错误态、轮询刷新。

已挂到左栏图标，成为一级页面。

## 7. 安全

- 出站前脱敏：密钥、token、私钥、`password=` 类赋值，替换为 `[已脱敏]`。
- 记录一律当"数据"注入，不当指令；只有 verified 进简报。
- 服务器只存记录，不存原始对话；token 走请求头，可按项目分权（v0.2）。

## 8. 路线图

- v0.1（本仓库）：hub + 插件工具 + 简报 + 设置页面板 + 手动新建/审核。
- v0.2：回合结束自动草稿、待审徽标、成员心跳、按板卡筛选、离线重试队列。
- v0.3：`supercedes` 链、环境指纹失效、台架租约（嵌入式专属）。
