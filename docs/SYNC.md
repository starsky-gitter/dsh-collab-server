# 弹性同步网络设计

目标：每台机器都是一个节点，本地永远可写；节点之间自动收敛。没有单点，主机（hub）关机不影响别人继续写入和互相同步。

## 1. 数据模型：事件日志，而不是可变记录

每个节点保存一个**只追加的事件日志**：

```json
{"origin":"n_a1b2","seq":7,"hlc":"0001730000000000-0003-n_a1b2","at":"…","type":"record","record":{…},"by":"zhangsan"}
{"origin":"n_a1b2","seq":8,"hlc":"…-0004-n_a1b2","at":"…","type":"status","id":"r_x","status":"verified","by":"lisi","note":"上板验证"}
```

- `origin` = 节点 id，`seq` = 该节点的本地递增序号。
- 记录本体**不可变**；改状态是追加一条 `status` 事件。
- 状态冲突用 HLC（混合逻辑时钟，`wall-counter-node`，字符串排序即时间排序）做 last-writer-wins；历史全部保留。

这样合并是幂等的：同一条事件收到多少次都只应用一次，永远不存在"覆盖掉别人的修改"。

## 2. 同步：一轮两个请求

每个节点有摘要 `digest = { origin: maxSeq }`——"我见过每个节点到第几条"。

```
A → B: POST /api/sync {digest: A 的摘要}
B → A: {digest: B 的摘要, events: A 缺的事件}
A 合并，然后
A → B: POST /api/sync {digest: A 的新摘要, events: B 缺的事件}
B 合并
```

一轮结束双方收敛；有更多积压就再跑一轮（单轮上限 200 条）。**没有推送、没有长连接**，只是一个定时器每 15 秒对每个 peer 跑一次。任何一方下线，另一方继续本地写，重新上线后自动补齐。

## 3. 拓扑：主从 + 可选全互联

推荐先上主从，mesh 以后再说：

```
主机（总库，expose: true，接受入站）
  ▲        ▲        ▲
  │        │        │   从机主动连主机（primary），不需要入站端口
从机 A   从机 B   从机 C
```

- 从机配置 `primary: http://主机:7420`；主机配置 `expose: true`、`peers: []`。
- 主机离线：从机照常写本地日志，待同步计数增加；每 15 秒重试，恢复后第一轮补传。
- 从机离线：主机继续写；从机恢复后同一轮把主机的新记录拉下来。
- 要升级成 mesh，再给节点加 `peers` 互相填地址即可，协议不变。

## 4. DSH 里怎么落地

每个 DSH 实例在插件里**内嵌**一个节点（`plugin/core.js`），监听 `peerPort`（默认 7420）：

- 插件工具和面板都走 `http://127.0.0.1:<port>`，和现在完全一样；
- 节点在后台与其他 peer 同步；
- 数据放在 DSH profile 目录下，卸载插件不删数据；
- 不装 Node、不另起进程、不开终端——成员只需要装一次插件。

独立的 `hub/server.js` 仍然保留，给"没有 DSH 的常驻机器"或跨网段中继用。

## 5. 人工只剩审核

- 回合结束自动生成草稿（`turn-stopping`）：从本轮的用户请求、最终回答、构建/烧录/串口结果里抽一条 `draft`，标记 `auto: true`。
- 草稿立即进入本地日志并同步给所有人；任何人点「通过验证」才变成可信记录。
- 没有"发送"动作，没有"同步"按钮。

## 6. 冲突与边界

| 情况 | 行为 |
|---|---|
| 两台机器离线各写一条 | 各自 `seq` 独立，合并后都在；互不覆盖 |
| 两人同时改同一记录状态 | HLC 大的赢，历史两条都保留 |
| 事件乱序到达 | 按 `origin` 缓冲，缺口补齐后再应用 |
| 状态先于记录到达 | 暂存为 orphan，记录到达后补应用 |
| 节点 id 冲突 | 不可能：id 在首次启动时生成并持久化 |

## 7. 安全边界（v1）

共享 team token，明文 HTTP。也就是说：**能连上端口的同网段机器都能写**。缓解手段是审核闸门 + 记录按数据注入；真正的账号体系留给云端模式。

## 8. 前提与决策

mesh 能否成立取决于两个网络事实：

1. 机器之间能否互相访问端口（同一内网、无客户端隔离、防火墙放行 7420）。
2. DHCP 环境下地址会变，需要固定 IP、DHCP 保留，或者发现机制。

如果第 1 条不成立，就退回"常驻中继 + 本地队列"：每台机器本地可写、上线后与中继同步，收敛语义完全一样，只是少一条直连路径。
